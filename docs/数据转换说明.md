# 将第三方持仓数据转换导入 EcoCal — 详细操作指引（供转换 Agent 使用）

> 本文档是一份**给执行转换任务的 AGENT 的完整提示词**：说明 EcoCal（目标系统）的数据格式、第三方数据的字段映射规则、转换规则、输出模板与验证方法。照此执行即可生成一份 EcoCal 可直接导入的 JSON 备份文件。

---

## 0. 任务目标

用户此前使用**另一个个人开发的持仓管理工具**记录资产，现要把数据迁移到 EcoCal。

你（转换 Agent）的产出物是**一个 JSON 文件**（EcoCal 备份格式，`ecocal-backup-YYYY-MM-DD.json`），用户可在 EcoCal 里通过「设置 → 数据管理 → 导入备份」导入。

**重要前提**：先拿到并仔细阅读源工具的**数据导出文件**（可能为 JSON / CSV / 数据库导出 / 备份文本等），理解其字段含义后再动手映射。**禁止**凭猜测编造字段，源数据缺失的信息应如实留空（或按第 5 节规则处理）并在交付说明中列出。

---

## 1. EcoCal 数据格式完整规范（目标格式）

### 1.1 存储与整体结构

EcoCal 是纯前端 PWA，数据保存在浏览器 `localStorage`，键名固定为：

```
ecocal.data.v1
```

存储的是一整个对象，其结构等同于导出备份的主体：

```jsonc
{
  "assets":    [ /* 产品数组，见 1.2 */ ],
  "valuations": [ /* 价值快照数组，v6 起恒为空 []，见 1.4 */ ],
  "trades":    [ /* 逐笔交易数组，见 1.3 */ ],
  "settings":  { /* 设置与汇率，见 1.5 */ }
}
```

**导出备份文件**在最外层再包一层元信息（用户从 EcoCal「导出」得到的就是这种）：

```json
{
  "app": "EcoCal",
  "version": 1,
  "exportedAt": "2026-10-22T07:00:00.000Z",
  "assets": [],
  "valuations": [],
  "trades": [],
  "settings": {}
}
```

> **导入校验规则（务必遵守，否则导入被拒）**：EcoCal 的 `importPayloadText` 只做一次 JSON.parse，然后检查 **`assets` 必须是数组** 且 **`valuations` 必须是数组**（二者缺一不可）。`trades` 缺省视为 `[]`，`settings` 缺省用默认值。因此你生成的 JSON **必须包含 `assets` 与 `valuations` 两个数组字段**（`valuations` 置 `[]` 即可）。

### 1.2 产品（assets[]）字段规范

| 字段 | 类型 | 必填 | 说明与取值约束 |
|---|---|---|---|
| `id` | string | ✅ | 全库唯一，被 `trades[].assetId` 精确引用。无格式要求，建议 `asset_<序号>`（如 `asset_1`）。**同一资产在所有交易中必须一致** |
| `name` | string | ✅ | 产品名称（如「沪深300指数基金」「招商银行」「美元现汇」） |
| `category` | string | ✅ | 大类，**必须是下列枚举之一**：`stock`（股票）、`fund`（基金）、`bond`（债券）、`deposit`（存款）、`wealth`（银行理财）、`insurance`（保险）、`fx`（外币）、`commodity`（商品）、`crypto`（数字货币）、`other`（其他） |
| `subCategory` | string | 建议 | 小类，**必须是该大类下的合法子项**（见 1.2.1）；未知子类可填该大类首个子项或 `其他` |
| `currency` | string | ✅ | 3 位大写币种代码：`CNY / USD / HKD / EUR / GBP / JPY / SGD / AUD / CAD / CHF` 或自定义 3 位大写。正则校验 `/^[A-Z]{3}$/`。**注意：外币（fx）产品固定为 `CNY`** |
| `foreignCurrency` | string | 条件 | **仅外币产品**填其外币代码（如 `USD`），其余产品置 `null`。导入时若非 fx 会被强制置 null，fx 缺失时默认 `USD` |
| `symbol` | string | 可选 | 股票行情代码（如 `sh600036`、`hk00700`、`usAAPL`、`bj430047`）。非股票置 `null`。不填不影响计算，只影响行情刷新 |
| `note` | string | 可选 | 备注，可为 `""` |
| `riskLevel` | string | 可选 | 风险等级 `R1`–`R5` 之一，或 `null` |
| `tPlusN` | number | 可选 | T+n 到账天数（非负整数），或 `null` |
| `startDate` | string | 可选 | 持有起始日 `YYYY-MM-DD`，或 `null`（v6 已不依赖，仅用于无交易时的持有天数兜底） |
| `principal` | number | — | **v6 已废弃，恒置 `0`**。若你给它赋了正数且该产品**无任何交易**，导入时会被自动迁移成一笔买入（见 1.6），非预期的应按第 5.5 节处理 |
| `quantity` | number/null | — | **v6 已废弃，恒置 `null`** |
| `minHoldDays` | number/null | — | 资产级最低持有天数（**v6 改为按每笔买入记录**，见交易字段），通常置 `null` |
| `lastPrice` | number/null | 持仓中建议填 | **当前单位价值**，语义见 1.2.2（决定市值/浮动盈亏计算） |
| `priceSource` | string/null | 可选 | `'manual'` 或 `'auto'`，表示现价来源；迁移数据建议 `'manual'` |
| `lastQuoteAt` | number/null | 可选 | 现价记录时间戳（ms），可为 `null` |
| `createdAt` / `updatedAt` | number | 可选 | 时间戳（ms），建议给一个值（无严格要求） |

#### 1.2.1 大类 → 小类合法取值（`CATEGORIES`）

```
stock:    A股 | 港股 | 美股 | 其他市场
fund:     货币型 | 债券型 | 混合型 | 指数型 | 股票型 | QDII | 其他
bond:     国债 | 企业债 | 可转债 | 其他
deposit:  活期 | 定期 | 大额存单
wealth:   固收类 | 权益类 | 混合类
insurance:年金险 | 增额寿险 | 其他
fx:       现汇 | 现钞 | 外汇理财 | 其他
commodity:黄金 | 原油 | 大宗商品 | 其他
crypto:   比特币 | 以太坊 | 其他
other:    其他
```

> **小类影响统计分组**（`assetGroupOf` 映射，用于统计页「资产类别」聚合）：
> `stock→股票`、`bond→债券`、`commodity→商品`、`crypto→数字货币`、
> `deposit→现金及等价物`、**`fund 且 货币型 → 现金及等价物`**、其余 `fund→基金ETF`、
> **`fx→现金及等价物`**、`wealth/insurance/other→其他`。
> 若源数据有「货币基金」请映射到 `fund` + 小类「货币型」，而不要用 `deposit`，否则分组口径会进错桶。

#### 1.2.2 `lastPrice` 的语义（因大类而异）——转换时最易出错点

EcoCal 内部统一按 **`市值 = 持仓数量 × lastPrice`** 计算（`tradePosition`：优先 `lastPrice`，缺失时**回退用该资产最近一笔成交价**估算市值，口径与组合走势图一致），因此 `lastPrice` 必须按以下口径填：

| 大类 | `lastPrice` 含义 | 换算方法 |
|---|---|---|
| `stock` | 每股单价（按 `currency` 计） | 直接填源数据的当前股价 |
| `fund` / `bond` / `wealth` / `insurance` / `commodity` / `crypto` / `other` | **单位净值/单位价值** | `lastPrice = 当前持仓总市值 ÷ 持仓份额`。若只持有 1 份（如大额存单），则 `lastPrice = 总金额` |
| `fx`（外币） | **汇率**：1 外币 = ? 人民币 | `lastPrice = 当前外币市值（人民币）÷ 持有外币数量`，即 1 外币兑人民币汇率 |

若 `lastPrice` 为空（`null`）且有持仓：市值按**最近成交价**回退估算（有买入交易时不再显示 `--`，仍计入汇总总额；多笔买入时取最后一笔成交价）；只有**已清仓**或**尚无任何交易**的资产市值才为 `null`。**仍建议对当前持有的资产填上当前市值/汇率**（回退值只是成本近似，无法反映真实波动）。

### 1.3 交易（trades[]）字段规范

EcoCal v6 的核心是「交易记录」：**所有持仓、成本、盈亏均由逐笔交易推导**（加权平均成本法），不做价值快照。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 全库唯一，建议 `trade_<序号>` |
| `assetId` | string | ✅ | **必须等于某资产 `id`**（大小写敏感、精确匹配） |
| `type` | string | ✅ | `'buy'` 或 `'sell'` |
| `date` | string | ✅ | `YYYY-MM-DD`，严格格式校验（`parseDate` 正则为 `/^(\d{4})-(\d{2})-(\d{2})$/`） |
| `quantity` | number | ✅ | 正数。语义 = 份额/股数；**外币产品 = 外币数量**。最多 4 位小数 |
| `price` | number | ✅ | 正数。单价；**外币产品 = 汇率（1 外币 = ? 人民币）**。最多 4 位小数 |
| `fee` | number | 可选 | 手续费（**按资产本币计**），默认 `0`，2 位小数 |
| `note` | string | 可选 | 备注，可为 `""` |
| `mode` | string | 建议 | 录入方式（仅影响编辑表单默认值，不影响计算）：`'qty'`（份数×单价）/ `'amount'`（总金额）/ `'exchange'`（兑换，仅外币）。建议按「股票→qty，非股票→amount，外币→exchange」填 |
| `minHoldDays` | number/null | 可选 | **仅买入**且非股票：该批买入的最低持有天数（整数）。卖出/其他置 `null` |
| `createdAt` | number | 可选 | 时间戳（ms），建议给一个值 |

**计算口径（转换时用来验证结果的公式）：**

```
买入：成本 += 数量 × 单价 + 手续费；持仓 += 数量
卖出：均价 = 成本 ÷ 持仓；卖出额 = 数量 × 单价 − 手续费
     已实现盈亏 += 卖出额 − 数量 × 均价；成本 −= 数量 × 均价；持仓 −= 数量
市值  = 持仓 × 现价（现价优先 lastPrice；缺失时回退最近成交价；持仓>0 且两者之一有值才计算）
浮动 = 市值 − 成本；总盈亏 = 浮动 + 已实现
持有天数 = 首笔交易日(或 startDate) → 今天 的自然日差
年化(单利) = 浮动 ÷ 成本 × 365 ÷ 持有天数（成本>0 且有浮动时）
```

> **卖出序列要求**：EcoCal 界面提交时会拦截「卖出超持仓」；虽然导入直接写 state 不校验（`Calc.tradePosition` 只会把超卖钳制为 0 持仓、不报错），**仍应生成合法序列**（任一日期累计卖出 ≤ 累计买入）。按日期升序逐笔核对。

### 1.4 价值快照（valuations[]）

v6 起该数组**恒为空**。请直接输出 `"valuations": []`。

> 若你拿到的是旧的 v5 版 EcoCal 备份（带 valuations 价值记录），EcoCal 导入时会自动迁移（见 1.6），无需你处理。

### 1.5 设置（settings）

| 字段 | 类型 | 说明 |
|---|---|---|
| `baseCurrency` | string | 基准币种，默认 `"CNY"` |
| `rates` | object | **汇率表**：`{ "USD": 7.2, "HKD": 0.92 }`，含义是「1 币种 = X 基准币种」。**凡是资产的 `currency` ≠ 基准币种的，都应提供对应汇率**，否则该资产无法换算进总额（统计会缺一块） |
| `liabilities` | number | 负债总额（基准币种），默认 0 |
| `singleAssetCap` | number | 单一标的上限阈值（%），默认 20 |
| `riskFreeRate` | number | 无风险年化利率（%），默认 2 |
| `demoDismissed` | boolean | 演示数据提示是否已关闭 |
| `autoFetchRates` / `autoQuote` | boolean | 联网自动获取汇率/行情的开关，迁移可保持默认 |
| `ratesUpdatedAt` / `ratesSource` | number/string | 联网汇率时间戳与来源，可 `null` |
| `quotes` / `kline` | object | 行情/日K缓存（运行时缓存），输出 `{}` 即可 |

迁移时 `settings` 最少给：`{ "baseCurrency": "CNY", "rates": {...} }`。

### 1.6 导入后的自动行为（务必知晓）

`applyPayload` 写入后会自动执行 `migrateToV6()`：

1. **外币兜底**：fx 缺 `currency` → 置 `"CNY"`；缺 `foreignCurrency` → 置 `"USD"`；非 fx 的 `foreignCurrency` 强制置 `null`。
2. **旧快照迁移**：对**没有任何交易**且 `principal > 0` 的资产，自动生成一笔买入（日期 = `startDate` 或今天；`quantity` 有值用之否则为 1；`price = principal/quantity`；fee=0；note=`由旧数据迁移（原本金 X）`），并用 `lastPrice`（若有）或成本价兜底其现价。
3. `valuations` 清空为 `[]`。

因此：**如果你已经为某个资产生成了交易，就别再给它 `principal > 0`**（会重复历史）；**如果你刻意把某产品做成「监察表」（只跟踪不记账，如只看不买的股票），请给它 `principal: 0` 且无交易**，否则自动生成一笔买入会违背你的意图。

## 2. 转换总流程（Agent 执行步骤）

```
① 读取源工具导出文件 → 列出其全部字段与含义（形成源 Schema）
② 按第 3 节映射表把每个产品/每条记录映射为 EcoCal 字段
③ 按第 4 节规则处理数量、单价、市值、日期、费用、外币等口径
④ 组装 JSON（结构见第 5 节模板），确保 assets/valuations 两个数组存在
⑤ 用第 6 节「验证方法」自检：结构校验 → 计算校验（node 脚本）→ 可选手工导入
⑥ 输出 ecocal-backup-YYYY-MM-DD.json + 一份简短的「转换说明」（遗漏/假设清单）
```

## 3. 字段映射表（通用）

| 源工具字段（示例名） | → EcoCal | 处理说明 |
|---|---|---|
| 产品 ID / 主键 | `assets[].id` | 生成新 ID；**同一产品所有交易必须引用同一个 id** |
| 产品名 / 简称 | `assets[].name` | 直接映射；可在名称后加币种/类别以区分同名资产 |
| 类别 / 类型 | `assets[].category` | 映射到 1.2 的 10 个枚举之一（见 4.1 分类映射） |
| 细分/子类别 | `assets[].subCategory` | 映射到 1.2.1 合法子项 |
| 币种 | `assets[].currency` | 3 位大写代码；外币产品统一 `CNY` |
| 成本 / 本金 / 买入总额 | 由交易推导 | **不写** `principal`（置 0）；若源只有总额无明细，见 4.5 |
| 当前市值 / 现值 | `assets[].lastPrice` | 按 1.2.2 换算成「单位价值」；且赋 `priceSource:'manual'` |
| 开始/买入日期 | `trades[].date` / `assets[].startDate` | 统一 `YYYY-MM-DD`（见 4.3） |
| 备注 | `assets[].note` / `trades[].note` | 产品级进 `note`，逐笔说明进交易 `note` |
| 风险等级 | `assets[].riskLevel` | 若源为中文等级（低/中低/中/中高/高）→ `R1/R2/R3/R4/R5` |
| 份额 / 股数 | `trades[].quantity` | 见 4.4 数量口径 |
| 成本单价/买入价 | `trades[].price` | 见 4.4；外币为汇率见 4.6 |
| 手续费/佣金 | `trades[].fee` | 买入手续费计入成本；卖出手续费从回收中扣（见 1.3 公式） |
| 买卖方向 | `trades[].type` | `buy` / `sell` |
| 赎回/锁定期 | `trades[].minHoldDays` | 每笔买入可单独设置（如基金持有 7 天免赎回费、定存锁定期） |
| 交易时间戳 | `createdAt` | 有则用日期转毫秒，无则给任意一致值 |
| 汇率（外币→本币） | `settings.rates` + 交易 `price` | 见 4.6 外币处理 |

## 4. 核心转换规则（按场景）

### 4.1 类别映射（源 → EcoCal 枚举）

| 源工具类别（常见写法） | EcoCal `category` | `subCategory` 建议 |
|---|---|---|
| 股票 / 个股 | `stock` | A股 / 港股 / 美股 / 其他市场 |
| 基金（货币） | `fund` | **货币型**（统计归「现金及等价物」） |
| 基金（债券/混合/指数/股票/QDII） | `fund` | 债券型/混合型/指数型/股票型/QDII |
| 债券/国债/可转债 | `bond` | 国债/企业债/可转债 |
| 存款/定期/大额存单 | `deposit` | 活期/定期/大额存单 |
| 银行理财 | `wealth` | 固收类/权益类/混合类 |
| 保险/年金/增额寿 | `insurance` | 年金险/增额寿险/其他 |
| 外币/外汇/美金 | `fx` | 现汇/现钞/外汇理财/其他 |
| 黄金/贵金属 | `commodity` | 黄金（纸币口记账用价格） |
| 数字货币/BTC/ETH | `crypto` | 比特币/以太坊/其他 |
| 其他/未知 | `other` | 其他 |

### 4.2 币种处理

- 币种统一 3 位大写：人民币 `CNY`、美元 `USD`、港币 `HKD`、欧元 `EUR`、英镑 `GBP`、日元 `JPY`（日元金额显示 0 位小数）、新加坡元 `SGD`、澳元 `AUD`、加元 `CAD`、瑞郎 `CHF`；自定义币种也须 3 位大写字母。
- 基准币种默认 `CNY`。**凡 `currency !== baseCurrency` 的资产，必须在 `settings.rates` 提供汇率**（`"1 币种 = X 基准币种"`），否则跨币种汇总会缺项（界面上会有提醒）。
- 源数据若已把外币换算成人民币记账，则按人民币资产处理（`currency:'CNY'`）。

### 4.3 日期标准化

- 一律输出 `YYYY-MM-DD`（补零：`2025-01-05`，不要 `2025-1-5`）。
- 无日期来源时：产品级用 `startDate`（若源给了持有起始日），交易级优先用源买入/卖出日；实在没有，买入可用 `startDate`，卖出不可虚构。
- **交易排序**：转换后按 `date` 升序核对一遍（EcoCal 内部按日期排序计算，但保证序列合法总是正确的做法）。

### 4.4 数量与单价（非外币）口径

核心公式：**`成交金额 = quantity × price`**（正数；quantity 与 price 各 ≤4 位小数）。

| 源数据形态 | 转换方法 |
|---|---|
| 有份额 + 有成交总金额（或按价格算得出） | `quantity` = 份额，`price` = 总金额 ÷ 份额（保留 4 位） |
| 有总投入金额 + 无份额（如“买了 1 万元基金”且不知净值） | 方案 A（推荐）：用源给的「现净值」反推份额 `quantity = 金额/现净值`、`price` = 当时单价，若源只有买入总额无单价，**采用金额记账**：`quantity = 总金额`、`price = 1`（此时市值 = `lastPrice = 当前总金额` 即可，等同“1 份 = 整笔”）——这正是 EcoCal「总金额」录入的兜底语义 |
| 只有成本总额 + 数量 | `price = 成本/数量`（若手续费单独给出，先扣手续费再均摊，即 `price = (总金额−手续费)/数量`，fee 单列） |
| 定存/国债/保险等“一笔 = 一份” | `quantity = 1`，`price = 本金总额`，`lastPrice = 当前总价值` | 

### 4.5 源工具只有「当前快照」（本金 + 现市值）没有逐笔历史

按 EcoCal 的迁移惯例生成**一笔买入**（与 `migrateToTrades` 行为一致）：

```jsonc
{
  "id": "trade_1", "assetId": "asset_1", "type": "buy",
  "date": "2024-01-15",              // startDate 或买入日，无则今天
  "quantity": 800,                    // 源给份额则用之；否则 1
  "price": 37.5,                      // = 本金 ÷ 份额；无份额则 = 本金
  "fee": 0,
  "note": "由旧数据迁移（原本金 30000）",
  "mode": "amount",                   // 非股票；股票用 "qty"
  "minHoldDays": null,
  "createdAt": 1705296000000
}
```

同时给 `lastPrice` = 当前市值 ÷ 份额（无份额则 = 当前市值），`priceSource: 'manual'`。**产品字段 `principal` 一样置 0**（不要用旧迁移机制，避免双写）。

### 4.6 外币（fx）处理 —— 重点

EcoCal 外币记账约定：**用人民币买卖外币**。

- 资产字段：`category:'fx'`、`currency:'CNY'`、`foreignCurrency:'USD'`（真实的 3 位外币代码）。
- 交易字段：`quantity` = **外币数量**（如 2000 美元），`price` = **成交汇率**（1 外币 = ? 人民币，如 7.15），`mode:'exchange'`。人民币金额 = `quantity × price`。
- `lastPrice` = **当前汇率**（1 外币 = ? 人民币，如 7.22），`priceSource:'manual'`；市值 = 外币余额 × 当前汇率。
- `settings.rates` 里**不必**为外币再单独配 `USD` 汇率（fx 资产的会计本位已是人民币）；`rates` 主要服务 `currency` 非 CNY 的产品（如美元计价的 QDII 基金）。
- 源数据可能给出的是「现汇买入/卖出价」或「中间价」：成交汇率一律填**该笔交易实际计价用的汇率**；若源只有人民币收支和外汇数量两个数，用 `汇率 = 人民币金额 ÷ 外币数量` 反推（这正是 EcoCal「兑换」录入的做法，保证金额自洽）。

### 4.7 手续费

- `fee` 以**该资产本币**计（fx 产品按人民币计）。
- 买入手续费并入成本；卖出手续费从卖出额中扣（影响已实现盈亏）。若源数据把手续费已含在单价里且单独不可得，可置 0 并在转换说明中注明「手续费并入单价」。

### 4.8 最低持有天数 / 锁定

- 逐笔买入的锁定：写 `trades[].minHoldDays`（非股票买入）。例如定期存款锁 1095 天、基金 7 天免赎回费。
- 源如果只有“产品级锁定期”，把它**平分到每笔买入**（同一产品所有买入填同一值即可）。
- 无则 `null`。

### 4.9 其余产品属性

- `riskLevel`：有则按 R1–R5 映射；`tPlusN`：有则填非负整数；`note`：源备注转录。
- 股票 `symbol`：若源有代码且能匹配 EcoCal 规则就填（`sh600519`/`sz000001`/`bj430047`/`hk00700`/`usAAPL` 或裸代码 600519/000001/00700/KO）；拿不准就留 `null`（不影响计算，仅影响行情刷新）。

## 7. 常见陷阱速查

| 陷阱 | 后果 | 规避 |
|---|---|---|
| `assetId` 与资产 `id` 不匹配 | 交易“找不到产品”，持仓计算为空 | 生成后做一次引用完整性检查（见 6.1） |
| `category`/`subCategory` 不在枚举内 | 界面显示原样字符串、统计分组错乱 | 严格用 1.2.1 的枚举 |
| 币种小写 / 非 3 位 | 校验失败或汇率换算失效 | `/^[A-Z]{3}$/` |
| 外币产品 `currency` 填了 USD | 金额口径错乱（EcoCal 外币按人民币计） | fx 一律 `currency:'CNY'` + `foreignCurrency:'USD'` |
| `principal` 填了正数但没生成交易 | 导入时自动多一笔“迁移买入”，与预期不符 | 有交易的资产 `principal:0`；确实无交易的监察表资产也置 0 |
| `lastPrice` 填总市值而非单位价值 | 市值放大 `n` 倍 | 按 1.2.2 换算为「单位价值/汇率」 |
| 日期 `2025/01/05` 或 `2025-1-5` | 导入后无法按日期解析，持仓天数异常 | 严格 `YYYY-MM-DD` |
| 卖出数量超过累计买入 | 界面会拒绝，导入后持仓被钳为 0 | 用 6.2 脚本重放校验卖出序列 |
| 非基准币种资产未配 `settings.rates` | 该资产不参与总额与统计 | 逐资产检查 `currency` ≠ `baseCurrency` 的汇率齐全 |
| 有持仓但不填 `lastPrice` | 市值按最近成交价回退（对成本近似），不反映真实涨跌 | 对仍在持有的资产补填当前市值/汇率（`priceSource:'manual'`） |
| 用 Excel 另存/手工编辑 JSON 引入 BOM 或中文转义错误 | 导入解析失败 | 用 UTF-8 无 BOM、JSON 合法；交付前 `JSON.parse` 一次 |
| 源「分红/拆分」直接当卖出记 | 已实现盈亏虚增 | 分红可写进备注；若源把分红记为现金回收，需在转换说明中说明口径 |
